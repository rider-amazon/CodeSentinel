# Harness 总则

> 本文件是 Harness 工作流约束的"总则"，定义目的、原则、适用范围与工作流一句话。
> 配套索引见 `INDEX.md`；整体说明见 `README.md`。

## 目的
为 AI 协作开发提供一套**可执行的约束机制**：在动手改代码前先"计划"（明确范围与验收），改动时"执行"（只在范围内修改），完成后"核对"（按清单自测）。让每一次改动可审计、可回退、可复现，避免 AI 擅自扩大改动范围或引入未比选的新依赖。

## 原则
1. **先计划、后执行**：任何改动必须先写计划并经校验（`harness plan`），不得直接动代码。
2. **范围受控**：执行只能触及计划中列出的文件；越界改动在执行校验时被标记（`in_plan=false`）。
3. **失败即回退**：核对不过关时，带着报错与现象回到计划阶段收紧范围或改写验收标准，不得带病提交。
4. **机器可读优先**：计划/执行/核对用 JSON 模板，由 `scripts/harness.py` 按 schema 校验，减少主观歧义。
5. **不入库**：`harness/` 整体在 `.gitignore` 忽略，属于本机工作流工具，不随仓库分发或提交到 GitHub。
6. **假实现必须标注**：用临时假实现支撑功能时，必须在记录中明确标注"假实现"及原因，不得对外宣称已完成。

## 适用范围
- 本仓库（`oj-anti-ai`）的所有代码改动、文档修订、实验脚本调整。
- 单人开发或双人组（王嘉乐 / 吴鹏楚）协作时的流程对齐。
- 不适用于：一次性探索脚本、纯文档草稿（可跳过但建议留痕）。

## 工作流一句话
```
计划(plan.json) → 校验 → 执行(在 scope 内) → 记录(execute.json) → 核对(verify.json) → 失败回退
```
