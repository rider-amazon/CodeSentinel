## 二、MVP （Minimum Viable Product）范围

| 模块  | MVP 功能                                              |
| --- | --------------------------------------------------- |
| 前端  | 题目列表页、题目详情页（含防护开关：原始 / 机制一 / 机制二 / 组合）、提交与结果页       |
| 后端  | 题目数据服务（JSON/Markdown 题库）、判题引擎（受限子进程 + 输出比对，可降级模拟判题） |
| 机制一 | 同构多版本生成器：同一逻辑题 ≥3 版本，按会话确定性分配                       |
| 机制二 | 信息扰动器：干扰注入版 + 关键约束隐藏版                               |
| 实验  | 批量调度脚本：枚举（题目 × 防护状态 × 模型 × 重复），自动调用 AI 并记录          |
| 数据  | SQLite/CSV 留档：AI 原始输出、判定结果、耗时、时间戳                   |
| 文档  | README + 启动/复跑脚本                                    |

**MVP 规模基线**：≥8 道自拟题目 × 4 种防护状态 × 2 个 AI 模型 × ≥3 次重复（下限 192 次 AI 求解）。

**MVP 之外（不做）**：用户体系、生产级沙箱、赛事配套（滚榜/气球/打印）、反作弊指纹、公网部署、模型训练。

## 三、系统实现进度（同日追加）

**已全部完成并通过端到端验证（对应立项书 M2-M5）：**

1. **题库（10 道自拟题）**：`tools/build_problems.py` 生成 → `server/problems/*.json`。每题 3 个同构版本（背景/数值/变量名不同）+ 2a 干扰文本（蜜饵可检测）+ 2b 可隐藏关键约束 + 边界测试点；期望输出由标准解实跑得出，手写样例全部断言通过。
2. **后端（FastAPI）**：题目服务、机制一版本分配（会话确定性）、机制二扰动（干扰注入/约束隐藏，仅展示层）、判题引擎（受限子进程 + 超时控制 + 输出比对，AC/WA/TLE/RE/CE，C++ 检测 g++ 可选）、SQLite 留档（submissions / experiment_runs）。
3. **前端（原生 HTML/CSS/JS）**：题目列表、题目详情（防护开关 P0/P1/P2a/P2b/P3a/P3b + 重置会话换版本 + 代码提交 + 逐测试点判定明细）、提交记录、实验数据看板。
4. **实验模块**：`experiment/run_experiment.py`（枚举题目×防护×模型×重复，OpenAI 兼容 API，代码提取，自动判题，误导检测，断点续跑，`--mock` 本地演示模式）；`experiment/analyze.py`（通过率/误导率/判定分布 + 卡方检验 + 图表 → `report/`）。
5. **验证结果**：Web 判题闭环全通（含大小写坑测试点精确命中、TLE/CE 正确判定）；mock 全量实验 120 格（10 题 × 4 状态 × 3 重复）完成，统计趋势正确（P0 83.3% → P3 33.3%，误导率 0 → 63.3%）。

**下一步**：配置真实模型 API 执行正式对照实验（≥2 模型），人工复核误导判定，撰写结课大报告（M6）。
